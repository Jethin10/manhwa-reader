Manhwa Reader — how everything works

One Next.js 16 server scrapes five comic sources and one anime source, merges them into a single catalog, and serves it to a PWA and an Android shell. All persistent user data stays on the device.

Clients
Browser / installed PWAiOS-style UI, tab bar, Home Screen install via manifest.ts
Android appCapacitor WebView shell that opens the server URL (LAN or MANHWA_SERVER_URL)
Service worker sw.js: shell network-first with /offline fallback; static cache-first; /api/img cache-first (up to 800 images); anime never cached
On-device storagelocalStorage: library and bookmarks, reading progress, preferences, JSON backup and restore
⇄
Next.js server (Render, Node 22)
Pages: server components, "use cache" + cacheLife
/ home shelves · /search · /series · /manga · /series/[id] · /series/[id]/chapter/[chapterId] · /anime · /anime/[id] · /bookmarks · /settings
unified.ts: best-copy enginefindMirrors searches every source for the same title and matches on normalized titles. It merges the chapter lists, then picks the highest-quality source that has each chapter (versionsOf). Mirror search times out after 10 s and uploads after 20 s, so a dead source never blocks the page.
catalog.ts: provider registryOne interface per source: browse · series · chapters · chapter · pages. Ids are prefixed by source, e.g. mangakatana~21708~c200
/api/img image proxyHost allowlist, HMAC-signed URLs (IMAGE_SIGNING_KEY), per-source Referer, disk cache in tmp/manhwa-reader-img, HD option
/api/anime/*servers, stream and media: resolve and proxy HLS through signed URLs
source-http.tsPlain-HTTP fetch with a browser user agent. Pages are parsed with cheerio. No headless browser.
/api/healthReturns { ok, uptime } without touching any source

Reading a chapter, step by step

  1. You open a series. /series/[id] loads it from its own source through catalog.ts.
  2. unified.ts searches the other four sources in parallel and keeps matching titles as mirrors.
  3. Chapter lists are merged by number. Each chapter links to the best source that has it.
  4. The reader page asks that provider for its page list, e.g. MangaKatana's longest script array.
  5. Each page is rewritten to a signed /api/img?… URL.
  6. The proxy checks the host and signature, fetches with the right Referer, and caches the image on disk.
  7. The service worker caches the image on the device. Reading progress is saved to localStorage.

Failure handling

If…Then…
A source is downIts mirror search times out and the other sources still serve the chapter. Home shelves render empty instead of erroring.
The build runsconnection() defers the home shelves to request time, so builds never depend on sources.
The phone is offlineThe service worker serves the cached shell, cached pages, or /offline.
Render restartsIMAGE_SIGNING_KEY keeps signed image links valid. The disk image cache refills on demand.
Render sleepsUptimeRobot's 5-minute ping prevents it.
